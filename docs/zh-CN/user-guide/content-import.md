# URL 与文本导入

ApeRAG 支持三种方式向知识库添加内容:**上传文件** / **网址导入** / **粘贴文字**。所有方式进入同一个"上传暂存区",由用户二次确认后统一入库。

本文介绍 URL / 文本两种**非文件**导入方式。文件上传请看[上传文档](./document-upload.md)。

## 适用场景

### URL 导入

- **文章摘录**:把公开网页(技术文档 / 新闻 / 博客文章)抓取为 Markdown 入库
- **外部资料聚合**:把散落在网上的一组资料集中导入单一知识库
- **不方便下载文件时**:原始页面无 PDF / Word 下载入口,但内容可读

### 文本导入

- **快速录入短笔记**:粘贴会议纪要 / 临时想法,不需要专门做成文件
- **剪贴板内容直入**:从其他 App 复制文字段落后直接归档
- **补充已有知识库**:在现有 Collection 里追加一段说明性文字

## 前置条件

- 已创建至少一个知识库(Collection),并有上传权限(一般是 Collection Owner)
- URL 导入需要 ApeRAG 配置了网页抓取能力:
  - 默认路径使用 **Trafilatura** 做内容抽取(不需额外配置)
  - 若管理员在**系统设置**里配置了 **JINA API Key**,会先走 JINA 抓取,Trafilatura 作 fallback
- 两种方式都必须**在线**:接口是同步的,页面加载时必须连到后端

## 操作流程

### 1. 打开"添加文档"对话框

进入目标知识库的**文档列表**页 → 点击右上角"**添加文档**"按钮 → 弹出来源选择对话框:

```
┌──────────────────────────────────────────────────┐
│  向知识库中添加文档                          [×]  │
├──────────────────────────────────────────────────┤
│                                                  │
│  ┌────────────────┐  ┌──────────┐  ┌──────────┐ │
│  │  📁            │  │  🔗      │  │  📋      │ │
│  │  上传文件       │  │  网址    │  │  粘贴文字 │ │
│  └────────────────┘  └──────────┘  └──────────┘ │
│                                                  │
└──────────────────────────────────────────────────┘
```

根据需要选择"网址"或"粘贴文字"进入下一步。

### 2A. 网址导入

点击"🔗 网址"进入 URL 输入表单:

- **每行输入一个网址**,最多 **10 个**
- 仅支持 `http://` / `https://` 合法 URL
- 仅抓取**公开可访问**的页面;需要登录 / 付费墙 / captcha 的页面会失败
- 点击"**抓取并添加**",系统同步抓取全部 URL(10 个一般在 30 秒内完成)

抓取结果会实时显示:

- ✅ **成功**:该 URL 对应文档出现在上传暂存区,文件名取自页面标题(如 `示例文章标题.md`)
- ❌ **失败**:对话框内红字显示错误(例如 `页面无法访问(403)` / `页面为空`),其他成功 URL 不受影响

### 2B. 粘贴文字

点击"📋 粘贴文字"进入文本表单:

- **标题**(可选):会作为文件名(`${title}.txt`);不填则自动生成 `note-{timestamp}.txt`
- **内容**:粘贴或输入文字内容;无字数硬限,但建议单次 < 10000 字符以保证体验
- 点击"**添加**":前端本地把文字封装成 `.txt` 文件,走上传接口;几乎无等待

文本导入**完全在客户端封装**,不新增后端接口 — 与普通文件上传完全等价。

### 3. 确认入库

两种方式产出的文档都进入**上传暂存区**(与文件上传文档合并展示):

```
┌─────────────────────────────────────────────────────────────┐
│  暂存区(待确认)                                             │
├───────────────────────────────────────┬──────┬─────────────┤
│ 文档名                                 │ 大小 │ 状态        │
├───────────────────────────────────────┼──────┼─────────────┤
│ 📄 user_manual.pdf                    │ 5 MB │ ✅ 已上传    │
│ 🌐 示例文章标题.md(来自 URL)           │ 8 KB │ ✅ 已上传    │
│ 📝 我的笔记.txt                        │ 2 KB │ ✅ 已上传    │
└───────────────────────────────────────┴──────┴─────────────┘
                                    [保存到知识库(3 个文档)]
```

点击"**保存到知识库**"触发索引构建:

- 状态从 `UPLOADED`(暂存)转为 `PENDING` → `RUNNING` → `COMPLETE`
- 进入索引构建流程(文档解析 / 向量化 / 全文索引 / 知识图谱,按 Collection 配置)
- 构建完成后即可在对话 / 搜索场景里被检索到

未确认的 `UPLOADED` 文档会一直留在暂存区,你可以:

- 点击"**移除**"删除该文档(不入库)
- 继续添加更多来源后统一 confirm
- 退出页面再回来仍可看到暂存

## 关键行为与约束

### URL 抓取依赖哪个服务?

系统默认使用**开源 Trafilatura** 做正文抽取 — 对大部分新闻 / 博客 / 技术文档够用。

若管理员在系统设置配置了 **JINA Reader API Key**,系统**优先用 JINA**(质量更高,支持更多站点),失败时自动 fallback 到 Trafilatura。

### 单次 URL 数量硬限 10

这是后端 Pydantic schema 层面的约束:

- `urls` 数组 **必须 ≥ 1 且 ≤ 10**
- 超过会返回 `422 Unprocessable Entity`
- 同步执行 → 数量过多会拉长请求时间 → 刻意限制

需要一次性导入大量 URL 时,建议分多批触发。

### URL 抓取是同步的

当前实现是**同步等待**:请求会 block 到全部 URL 抓取完成(或失败)。前端一般设置 60 秒超时;若 JINA / Trafilatura 响应极慢会触发前端超时,但后端仍会完成当批次的抓取。

后续版本可能改为异步任务(提交任务 → 轮询 → 收结果),但 MVP 期间保持同步。

### 文本导入是纯前端操作

文本导入利用浏览器 `File API` 把字符串封装成 `File` 对象,走现有的 `POST /documents/upload` 接口 —**完全没有新后端代码**,因此:

- 支持的文本大小与文件上传硬限一致(单文件默认几 MB 级别)
- 中文 / emoji / 特殊字符都 OK(UTF-8 编码)
- 本地预览即时可见,几乎无上传等待

### 权限与 Owner

三种导入方式的权限模型与文件上传**完全一致**:

- 知识库 Owner 可以导入
- Marketplace 订阅用户 / 外部分享链接用户**无写权限**,三个按钮都不会展示
- 未登录用户访问会跳转登录页

## 文件命名规则

| 来源 | 命名规则 |
|---|---|
| 文件上传 | 保留上传文件原名 |
| URL 导入 | 取 HTML `<title>` 作为文件名,`.md` 后缀;若无标题则用 URL host 部分 + `.md` |
| 文本导入 | 优先用用户填的"标题" + `.txt`;否则 `note-{timestamp}.txt` |

命名会被 sanitize(去除非法字符 / 超长截断),最终文件名在暂存区可见。

## 常见问题

### 为什么我的 URL 抓回来是空的?

可能原因:

- 页面需要 JavaScript 渲染,Trafilatura 解析 DOM 后内容为空 — 这类站点建议配置 JINA API Key
- 页面强制登录 / 有 paywall / captcha
- 服务器拒绝 ApeRAG 的 User-Agent(少见)
- URL 实际 HTTP 状态码是 404 / 403 / 5xx(错误信息会显示具体原因)

### URL 抓取的 Markdown 里为什么有很多广告 / 导航内容?

Trafilatura 的正文抽取基于 DOM heuristics,对复杂前端会漏抽。JINA 质量明显更好。另外也可以 confirm 前在暂存区**下载并编辑**该 Markdown(移除不需要的段落)再重新上传。

### 粘贴的文本可以是 Markdown 吗?

可以 — 但文件扩展名是 `.txt`。系统会按 plain text 处理(不做 Markdown 解析渲染)。若希望保留 Markdown 渲染,建议先存成 `.md` 文件再**上传文件**。

### 一次抓 URL 多了会怎样?

超过 10 个 → `422 Unprocessable Entity`,前端会整体拒绝;请分批处理。
单次 URL 太慢导致前端 60 秒超时 → 前端报错,但**后端可能已把成功的 URL 产出 UPLOADED 文档**。刷新暂存区可以看到它们,去重一下重试剩余的。

### 失败的 URL 还能手动重试吗?

对话框内失败的 URL 不会自动重试。你可以:

- 保留对话框内的 URL 列表,修正后再次点击"抓取并添加"
- 只复制失败的 URL 重新打开对话框粘贴

### 能不能批量粘贴多段文字分别入库?

当前表单一次只能创建一个文档。需要多段 → 重复操作 N 次,或把多段合并为单篇粘贴后在对话 / 搜索时按小标题定位。
